# Pencil 完整 UI 设计优化提示词（Clouddo）

## 使用方式
- 按阶段从上到下执行，不要一次性全贴。
- 每阶段先看输出再进入下一阶段，避免设计发散。
- 每次都要求 Pencil 只改“当前阶段范围”。

---

## 全局上下文（每次开新会话先贴）
```text
你是资深产品设计师 + 设计系统设计师。
请为 Clouddo 设计完整桌面 UI（Windows 优先），并保证可直接落地前端实现。

产品模块：
1) 时间管理（待办池 + 时间轴日程 + 轻笔记）
2) 笔记（文件树 + 编辑器 + 预览/评论）
3) 设置（主题、快捷键、偏好项）
4) 快速浮窗（今日任务摘要 + 快捷操作）

目标：
- 现代简洁、可读性优先、信息层级清晰
- 亮色为主，支持暗色主题
- 高密度场景下保持可扫描性

约束：
- 不使用花哨装饰，不做无意义动效
- 优先可维护组件，不做无法复用的特例布局
- 保持跨页面一致的 spacing / radius / color / typography
```

---

## Phase 1：信息架构与线框
```text
基于上述上下文，先输出低保真设计，不做高保真视觉。

请交付：
1) 全局信息架构（页面树 + 关键入口）
2) 侧边栏导航结构（主入口、次入口、状态提示）
3) 四个模块的低保真线框（每页核心区块 + 区块职责）
4) 每页主要交互路径（从进入到完成任务）

输出格式要求：
- 每个页面给出「目标」「区块结构」「关键操作」
- 最后输出一份“设计风险清单”（最多 5 条）
```

---

## Phase 2：设计系统（Token 先行）
```text
现在只做设计系统，不改页面结构。

请输出并应用：
1) 颜色体系（primary / neutral / semantic / dark mode）
2) 字体体系（标题、正文、说明、数字）
3) 间距体系（4/8 基线，组件内外间距规则）
4) 圆角与阴影体系
5) 图标风格规则

输出格式要求：
- 以 token 清单形式输出（命名 + 示例值 + 使用场景）
- 明确哪些 token 是全局，哪些是模块专用
```

---

## Phase 3：时间管理页（重点）
```text
请设计“时间管理”高保真页面：
- 左栏：待办池（分组、优先级、完成态、编辑入口）
- 中栏：时间轴（日/周/月切换，任务块拖拽反馈）
- 右栏：轻笔记（工具栏 + 输入区 + 占位提示）

必须包含状态：
- 空态、满载态、拖拽态、选中态、完成态、冲突提示态

输出格式要求：
- 先给布局说明，再给视觉说明
- 最后给组件清单（可复用 / 页面专用）
```

---

## Phase 4：笔记页
```text
请设计“笔记模块”高保真页面：
- 左：文件树（搜索、新建、重命名、删除）
- 中：编辑器（工具栏、编辑态、预览态）
- 右：评论/批注区

必须包含状态：
- 无文档、长文档、搜索无结果、评论为空、评论高亮定位

输出格式要求：
- 列出关键交互：粘贴、格式化、切换模式、评论定位
- 给出错误与恢复机制（例如误删、撤销）
```

---

## Phase 5：设置页 + 快速浮窗
```text
请完成两个页面：
1) 设置页：主题、快捷键、偏好、数据相关
2) 快速浮窗：今日任务摘要、快速完成、回主应用入口

要求：
- 设置页分组清晰，危险操作单独区域
- 浮窗在小尺寸下仍可快速操作（避免拥挤）

输出格式要求：
- 分别给出默认态 + 极端态（项很多/内容很少）
```

---

## Phase 6：交互规范与可交付性检查
```text
请对全应用补齐交互规范，不再改动主布局。

必须覆盖：
- hover / active / focus / disabled / loading / error / success
- 弹窗、Toast、确认删除、撤销条
- 键盘可达性与可读性（最小可访问性要求）

最后输出：
1) 组件状态矩阵
2) 设计-开发对齐清单（前端实现注意点）
3) MVP 开发优先级（P0/P1/P2）
```

---

## 一键收敛提示（用于“效果跑偏时”）
```text
当前输出偏离目标。请只做收敛，不做风格探索：
- 保留现有页面结构
- 统一 spacing、字体层级、按钮规格、卡片边界
- 降低视觉噪音，提升信息密度可扫描性
- 输出前后差异点（最多 10 条）
```

---

## 给 Pencil 的通用约束短句（可附加在任意阶段）
```text
仅输出当前阶段范围，不跨阶段改动。
不要引入新的页面。
优先复用组件，不创建重复组件。
输出必须可直接用于前端实现。
```
